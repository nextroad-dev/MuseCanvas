## 计划：Onboarding 引导页面 + 简化 env 配置

### 背景

当前新用户部署 MuseCanvas 需要手动填写 7 个 env 变量才能启动，且首个管理员通过 `seed.ts` 的 `ADMIN_EMAIL` 静态创建。用户希望做一个全流程引导页面，最小化 env 配置成本，让用户克隆后一条命令启动、浏览器中完成全部配置。

### 整体流程

```
用户克隆仓库 → pnpm compose:up → 浏览器打开 localhost:8080
→ 自动跳转 /setup 引导页面
→ Step1: 设置管理员邮箱（OTP 验证）
→ Step2: 配置供应商凭据（API Key）
→ Step3: 从预设创建模型
→ Step4: （可选）启用提示词优化
→ Step5: （可选）配置 OAuth 登录
→ 完成 → 跳转 /generate 开始创作
```

### 阶段 1：Env 自动生成 + seed.ts 改造

**1.1 新建 `scripts/generate-env.mjs`**

如果 `.env` 不存在，自动生成一份包含随机密钥的 `.env`：

```bash
POSTGRES_PASSWORD=<random hex 24>
SESSION_SECRET=<random hex 32>
S3_ACCESS_KEY_ID=<random hex 12>
S3_SECRET_ACCESS_KEY=<random hex 28>
OAUTH_CREDENTIALS_ENCRYPTION_KEY=<random hex 32>
PROVIDER_CREDENTIALS_ENCRYPTION_KEY=<random hex 32>
PROMPT_TEMPLATE_INDEX_PATH=./Template/index.json
# ADMIN_EMAIL 不再需要，由引导页面设置
```

如果 `.env` 已存在则跳过，不覆盖用户已有配置。

**1.2 修改 `package.json`**

`compose:up` 脚本前置 `generate-env`：
```json
"compose:up": "node scripts/generate-env.mjs && pnpm prepare:prompt-templates && docker compose up --build -d"
```

**1.3 修改 `packages/database/src/seed.ts`**

`ADMIN_EMAIL` 未设置时不再 throw，改为跳过并输出提示：
```ts
const email = process.env.ADMIN_EMAIL?.trim().toLowerCase()
if (!email) { console.log('ADMIN_EMAIL not set; first admin will be created via onboarding'); await db().end(); return }
```

**1.4 修改 `compose.dev.yaml`**

`ADMIN_EMAIL` 改为可选（`${ADMIN_EMAIL:-}`），不再阻塞容器启动。

**涉及文件**：`scripts/generate-env.mjs`(新)、`package.json`、`packages/database/src/seed.ts`、`compose.dev.yaml`

### 阶段 2：后端 Setup API

**2.1 新增 `GET /api/setup/status`**

公开端点，检查是否存在管理员：
```sql
SELECT count(*)::int FROM users WHERE role='admin' AND deleted_at IS NULL
```
返回 `{ setupComplete: boolean }`。

**2.2 新增 `POST /api/setup/admin/request`**

公开端点，仅在无管理员时可用。复用现有 OTP 逻辑（限流、邀请码检查跳过），发送验证码到指定邮箱。

**2.3 新增 `POST /api/setup/admin/verify`**

公开端点，仅在无管理员时可用。验证 OTP 后创建 `role='admin'` 用户并签发 session cookie。

**实现方式**：在 `route.ts` 的 GET/POST handler 顶部添加 setup 路由分支（在 `requireActor` 之前），调用新模块 `src/modules/setup/handlers.ts`。

**涉及文件**：`apps/api/app/api/[...path]/route.ts`、`apps/api/src/modules/setup/handlers.ts`(新)

### 阶段 3：前端引导页面

**3.1 新增路由和守卫**

- 新增路由 `/setup`，`meta: { public: true }`
- 修改 `guards.ts`：首次导航时调用 `GET /api/setup/status`
  - 如果 `setupComplete: false`，除 `/setup`、`/terms`、`/privacy` 外全部重定向到 `/setup`
  - 如果 `setupComplete: true`，正常路由

**3.2 新增 `features/setup/` 功能模块**

- `stores/setup.ts` — setup store，管理步骤状态、调用 admin store 复用已有 action
- `views/SetupPage.vue` — 多步骤引导向导

**3.3 引导步骤设计**

| 步骤 | 标题 | 内容 | API 调用 | 可跳过 |
|------|------|------|----------|--------|
| 1 | 设置管理员 | 邮箱输入 → OTP 验证 → 创建管理员 | `POST /api/setup/admin/request` + `POST /api/setup/admin/verify` | 否 |
| 2 | 配置供应商凭据 | 表单：名称 + 适配器(openai/seedream/anthropic) + API Key + Base URL | `POST /api/admin/provider-credentials` + `POST .../test` | 是（但提示未配置无法生图） |
| 3 | 创建模型 | 从预设列表勾选，自动关联匹配的凭据 | `GET /api/admin/model-presets` + `POST /api/admin/models` | 是 |
| 4 | 提示词优化 | 如果有语言模型，选择并启用 | `PATCH /api/admin/prompt-optimization-settings` | 是 |
| 5 | OAuth 登录 | 显示 GitHub/Google redirect URI，输入 Client ID/Secret | `GET /api/admin/oauth-providers` + `PATCH /api/admin/oauth-providers/{provider}` | 是 |
| 6 | 完成 | 显示配置摘要，点击进入创作 | 无 | — |

步骤 2-5 复用 `useAdminStore` 的现有 action（`createProviderCredential`、`createModel`、`updatePromptOptimizationSettings`、`updateOAuthProvider`），不需要新增管理 API。

**3.4 UI 设计**

- 顶部步骤指示器（1→2→3→4→5→完成）
- 每步卡片式表单，底部"上一步 / 下一步 / 跳过"按钮
- 步骤 2 支持添加多个凭据（列表 + 新建表单）
- 步骤 3 预设以卡片网格展示，点击勾选
- 遵循 `docs/design-system.md`，验证 375/768/1024/1440px 视口

**涉及文件**：`apps/web/src/app/router/index.ts`、`apps/web/src/app/router/guards.ts`、`apps/web/src/features/setup/stores/setup.ts`(新)、`apps/web/src/features/setup/views/SetupPage.vue`(新)、`apps/web/src/shared/types/index.ts`(新增 setup 相关类型)

### 注意事项

1. **安全**：setup 端点仅在无管理员时可用，创建后立即关闭。OTP 限流复用现有 `limited()` 机制。
2. **密钥持久化**：`generate-env.mjs` 生成的密钥写入 `.env` 文件，Docker volume 持久化数据库和 S3 数据，重启后密钥不变。
3. **复用现有 API**：步骤 2-5 完全复用 admin store 的现有 action，不新增管理端 API。
4. **渐进式**：每步可跳过，用户可以先跳过所有可选步骤直接开始使用，后续在管理后台补全。
5. **文档规范**：遵循 `docs/AGENTS.md` 的 design → impl → result 链路。
